# 邻近图压缩索引：融合技术设计与实验方案

> 目标会议：DASFAA（B 类检索方向）。核心思路来自导师 idea：邻近图（HNSW）上做两步压缩——向量压缩（RaBitQ）+ 图结构压缩（重排序 + delta 编码）。

---

## 一、三块如何融合（技术设计）

### 1. 总体架构

整体是一个 HNSW 邻近图索引，做**两层压缩**：

- **层 1（向量压缩）**：RaBitQ 把每个 D 维向量压成 D-bit 码（1 bit/维）。
- **层 2（图结构压缩，核心新贡献）**：对图节点**重编号**（graph reordering），让相邻节点编号相邻；邻接表改用 **delta 编码**存储。

检索流程不变（HNSW 分层贪心 + 底层 beam search），图拓扑不变 → **重排序不改变 recall**（Coleman 已论证，只改内存布局）。

省内存主要来自层 2；层 1 的作用是"把图结构变成内存大头"，构成动机，同时提供可叠加的向量压缩收益。

### 2. 三块的定位

| 块 | 论文 | 在融合中的角色 |
|---|---|---|
| 邻近图 | HNSW (Malkov & Yashunin) | 索引骨架：检索算法、图拓扑、分层结构 |
| 向量压缩 | RaBitQ (Gao & Long, SIGMOD'24) | 压向量（D 维→D bit）+ 无偏距离估计 |
| 图重排序 | Coleman et al. (arXiv:2104.03221) | 重编号 + delta 编码，压图结构 |

### 3. 核心设计决策（已敲定，附理由）

#### 3.1 重编号方案

- **目标函数选「带宽最小化 / 线性排列」（RCM / MLINA），不要用 Gorder。**
  理由：delta 要小 ⟺ 相邻节点编号差小 ⟺ RCM（min 最大差值）或 MLINA（min 差值之和）的目标；Gorder 优化的是"缓存共享边数"，不直接压 delta。
- **起步用 RCM**：`scipy.sparse.csgraph.reverse_cuthill_mckee` 有现成实现，O(|V|+|E|)、几乎免费，且直接给"最大差值"上界（适配定宽编码）。MLINA 作为后续优化（平均差值更小 → 压缩率更高，但 NP-hard 启发式更慢）。
- **多层处理：只在 layer-0（底层大图）上做一次全局重编号，同一顺序套用到所有上层。**
  理由：layer-0 占绝大多数边；跨层用同一 ID，搜索降层时无需 ID 映射表。可选扩展：用"各层加权并"做重编号（layer-0 权重更高）。
- **邻接表排序**：重编号后把每个节点的邻居按新 ID 升序排序——只改访问顺序、不改邻居集合 → recall 不变。

#### 3.2 Delta 编码方案

- **编码约定（推荐 gap 编码）**：第一个邻居存绝对 ID（varint 或 4 字节），后续邻居存**相邻差值** `neighbor[i] - neighbor[i-1]`。相比"相对第一个邻居"的 delta，gap 在存在远跳邻居时更省（只有一个 gap 大，其余仍小）。
- **定宽 vs 变长**：
  - 定宽 b 位（8/10/12/16 位）：解码快、随机访问简单；gap 超 `2^b-1` 时用"转义 + 溢出表"兜底。
  - 变长 varint（LEB128）：更省，但分支多、解码慢。
  - **起步用 8 位定宽**，随后扫 8/10/12/16 位 + varint 画空间曲线做优化对比。
- **量化示例（SIFT1M 尺度）**：M=16、Mmax0=32、mL=1/ln16≈0.36 → 平均 ≈38 边/节点。原始 4 字节/边 = 152 字节/节点；delta 后平均 gap ≤255 → 1 字节/邻居 ≈ 38 字节/节点，**图结构省约 4×**。

#### 3.3 向量压缩集成（RaBitQ × 图搜索）

- **索引期**：归一化（按簇质心或全局质心）、采样随机正交阵 P、为每个向量算 D-bit 码 x̄_b、预存 ⟨ō,o⟩。
- **查询期**：算 q′=P⁻¹q 并量化为 4-bit q̄；遍历图时对访问到的节点用**位运算**（bitwise-and + popcount）算 ⟨ō,q⟩，估计内积 ⟨ō,q⟩/⟨ō,o⟩，再换算成平方距离做候选选择；最后对 top-K 候选用**精确距离**重排。
- **注意**：图搜索是逐节点访问，不适合 RaBitQ 的 batch/SIMD 路径 → 用其 single-vector 位运算实现（论文中比 PQ-single 快约 3×）。
- **raw 向量存储策略**（决定"总内存"故事怎么讲）：
  - **模式 A（内存精确）**：raw 向量 + 码都放内存 → 向量不省内存，只省距离计算时间。
  - **模式 B（压缩内存）**：只存 D-bit 码，raw 向量放 SSD，重排 top-K 时按需读回（DiskANN 风格）。
  - 主实验用**模式 B** 讲"总内存大幅下降"；模式 A 作对照，隔离向量压缩的独立贡献。

#### 3.4 查询期解码开销

- delta 解码是新增查询成本；用 8 位定宽顺序解码，开销很小；且内存布局更连续，可能反而更快（Coleman 的 cache 收益）。
- 关键实验指标：**同 recall 下查询时间是否显著变差**。

#### 3.5 增量构建

- HNSW 增量插入照旧；重编号 + delta 编码作为**离线后处理**（建完图一次性做）。增量更新场景留 future work（或周期性 rebuild）。

## 二、实验技术方案

### 1. 数据集

- 先 **SIFT1M**（1M×128，三篇论文都用它、跑得快）；再 **GIST1M**（1M×960，高维）、**DEEP1M**（1M×96，低维）验证鲁棒性。
- 扩展性：SIFT 的 100k / 300k / 1M / 10M 子集。

### 2. Baseline 设计（每个 baseline 隔离一个贡献）

| # | 方法 | 向量存储 | 图结构 | 隔离出的贡献 |
|---|---|---|---|---|
| B0 | HNSW 原始 | raw float | 4 字节 ID | 上界（召回/时间/内存） |
| B1 | HNSW + 向量压缩 | D-bit 码 (RaBitQ) | 4 字节 ID | 只压向量 |
| B2 | HNSW + 图重排序（Coleman 式） | raw float | 重编号但仍 4 字节 | 只重排序、不 delta |
| B3 | HNSW + 图压缩 | raw float | 重排 + delta | 只压图（**核心**） |
| B4（本文） | 两层压缩 | D-bit 码 (RaBitQ) | 重排 + delta | 完整融合 |

补充基线（加分项）：
- **B1′**：HNSW + PQ/OPQ 向量压缩（替代 RaBitQ，说明 RaBitQ 更优或更简）。
- **B2′**：HNSW + degree-sort 重编号（廉价但弱，证明必须选对重排序目标）。

**关键对照**：
- B2 vs B3 → 证明"省内存的是 delta 编码，重排序本身不省"（这是与 Coleman 的根本区别）。
- B3 vs B4 → 证明"向量压缩与图压缩正交、可叠加"。
- B0 vs B4 → 总收益。

### 3. 评估指标

- **内存**：图结构字节/节点、向量字节/节点、总索引内存（MB）。
- **召回**：Recall@10、Recall@100（ground truth 用精确暴力算）。
- **查询时间**：平均 ms/query 或 QPS（单线程，10k 查询取均值）。
- **距离计算次数**（算法级效率，排除实现噪声）。
- 核心曲线：**memory vs recall**（同召回比内存）、**query time vs recall**。

### 4. 实验分组

1. **主实验**：B0–B4 在 SIFT1M 的 memory / recall / query time 三维对比，画 memory–recall 曲线。
2. **消融（ablation）**：
   - 重排序目标：RCM vs MLINA vs degree-sort vs 不排序 → 压缩率对比。
   - 编码宽度：8/10/12/16 位 vs varint → 空间 vs 查询时间。
   - 编码约定：gap vs delta-from-first。
   - 多层重编号：全局单序 vs 逐层各序。
3. **优化对比（如何优化 vs baseline）**：
   - 对每个 recall 档位选最优编码配置，报告"同召回下本文内存 vs B0"。
   - 参数扫描 M ∈ {8, 16, 32}：证明压缩在不同图密度下都有效。
   - 扩展性：N 从 100k→10M，看压缩率与查询时间趋势。
4. **与向量压缩联动**：RaBitQ vs PQ 在"图已压缩"下的 memory–recall 曲线（RaBitQ 用更短码达同精度 → 总内存更低）。

### 5. 第一步最小实验（本阶段就做，师兄要求 12 号前出结果）

1. 用 hnswlib 在 SIFT1M 建 HNSW（M=16, efConstruction=200）；若邻接表不好导出，退回自己写最小 HNSW 或用 nmslib。
2. 导出邻接表（每节点每层邻居 ID）。
3. 用 scipy `reverse_cuthill_mckee` 对 layer-0 图重编号。
4. 邻接表按新 ID 排序 + gap delta 编码（8 位定宽 + 溢出兜底）。
5. 对比 B0 vs B3：图内存（预期 ≈4×↓）、recall（应不变）、query time（解码开销）。
6. 若 B3 有效（内存↓且 recall 不掉），再叠 RaBitQ 得 B4，对比总内存。

产出：一张「图内存 / recall / query time」对比表 + 结论「有效 / 无效」。
